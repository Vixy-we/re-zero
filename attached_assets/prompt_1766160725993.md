Project Prompt: Personal Anime Bookshelf

## Core Concept
Design and build a personal-use web application that functions as a bookshelf-style anime library. This is a single-user tool intended to run locally or on a private host, acting as a "Personal Truth" log of watched content and future intent.
## Navigation & Organization
### The Three Shelves
Watched Shelf: A collection of anime the user has already completed.
Plan to Watch Shelf: A collection of anime the user intends to watch.
Global Database: A non-functional visual placeholder explicitly labeled "Coming Soon."
### Sorting & Filtering
A–Z Navigation: A toggleable system (alphabetical jump-links) to quickly navigate large libraries.
Rating Sort: Ability to view and reorder the library based on the personal 1–10 score.
Tag Logic: Anime can have multiple genre tags. Clicking a tag should filter the view to show all matching entries across the current shelf.
## The "Add Anime" Flow (Jikan Integration)
To eliminate manual data entry, the app will use the Jikan API (v4) to fetch metadata.
Search: User types a title $\rightarrow$ App fetches live results from Jikan.
Select: User clicks a result $\rightarrow$ App auto-fills name, poster_url, description, and tags.
Personalize: User manually inputs:Personal Rating (1-10)Personal Comment/NotesShelf Selection (Watched vs. Plan to Watch)
Save: The entry is committed to the local library.
## Data & Persistence
### Storage Strategy
Primary Storage: Use localStorage to persist the library within the browser.Initialization: On the first load, if localStorage is empty, the app should initialize using a default data.json structure.
### Data Schema
JSON{
  "id": "unique-uuid-or-mal-id",
  "name": "string",
  "poster_url": "string",
  "description": "string",
  "tags": ["Action", "Sci-Fi", "etc"],
  "status": "watched | plan_to_watch",
  "user_rating": 10,
  "user_comment": "string"
}
## UI / UX Philosophy
Bookshelf Metaphor: The main UI should resemble a library. Anime entries are represented as "Books" using their poster art.
Detail View: Clicking an anime "opens the book," triggering a clean overlay (Modal) that displays the full description, tags, user rating, and personal notes.
Responsive Design: A grid-based layout that scales elegantly from desktop monitors to mobile browsers.
Performance: Prioritize snappy navigation and immediate filtering over heavy 3D animations.
## Technical Constraints
Framework: React with Tailwind CSS.
Connectivity: Fetch data from Jikan API, but maintain offline viewing for already saved items via localStorage.
No PWA: Standard web application architecture only.
No Auth: No login or registration; the data is private to the browser session.
Scope Control: Do NOT implement the Global Database functionality yet. Focus entirely on the "Add" flow and the two active shelves.
### Technical Constraints & Stack
To ensure a modern, fast, and maintainable application, the following technologies should be used:
Frontend Framework: React.js (for component-based UI and state management).
Styling: Tailwind CSS (for rapid, responsive "Bookshelf" styling and layouts).
Backend/Scripting: Python (Flask or FastAPI) (optional, used if you want to save the JSON data to a local file system rather than just the browser).
Markup & Structure: HTML5 (semantic structure for accessibility).
API: Jikan API v4 (to fetch all anime metadata).
Icons: Lucide-React or FontAwesome (for shelf and navigation icons).
State Management: React Context API or Zustand (to keep the library data synced across shelves).
